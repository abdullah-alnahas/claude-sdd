## Command Patterns

### Pattern A: Context-Aware Commands (sdd-learn, sdd-replan)

These commands analyze recent conversation context to make decisions.

```
┌─────────────────┐
│ User invokes    │
│ /sdd-learn      │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Analyze recent  │
│ conversation    │
│ for corrections │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Propose update  │
│ to CLAUDE.md    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Confirm & write │
└─────────────────┘
```

### Pattern B: Scanner Commands (sdd-techdebt)

These commands scan the codebase and report findings.

```
┌─────────────────┐
│ User invokes    │
│ /sdd-techdebt   │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Scan codebase   │
│ using Grep/Glob │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Categorize &    │
│ report findings │
└────────┬────────┘
         │
    ┌────┴────┐
    │ --fix?  │
    └────┬────┘
    yes  │  no
         ▼
┌─────────────────┐
│ Offer fixes     │
│ with TDD        │
└─────────────────┘
```

### Pattern C: Mode-Switching Commands (sdd-challenge)

These commands change Claude's behavior/mode.

```
┌─────────────────┐
│ User invokes    │
│ /sdd-challenge  │
│ <mode>          │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Activate mode:  │
│ grill/prove/    │
│ elegant         │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Execute mode-   │
│ specific        │
│ behavior        │
└─────────────────┘
```

### Pattern D: Generator Commands (sdd-explain)

These commands generate artifacts (text, diagrams, HTML).

```
┌─────────────────┐
│ User invokes    │
│ /sdd-explain    │
│ <target>        │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Read target     │
│ code/concept    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Generate output │
│ in format:      │
│ text/ascii/html │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Write file or   │
│ display         │
└─────────────────┘
```

## Tool Usage

| Command | Primary Tools |
|---------|--------------|
| sdd-learn | Read (CLAUDE.md, conversation), Write (CLAUDE.md) |
| sdd-replan | Read (current state), EnterPlanMode |
| sdd-techdebt | Grep, Glob, Bash (for complexity analysis) |
| sdd-challenge | Read (diff, tests), Bash (run tests) |
| sdd-explain | Read (code), Write (HTML/text output) |

## Dependencies

```
sdd-learn
└── depends on: existing CLAUDE.md or notes/ directory

sdd-replan
└── depends on: EnterPlanMode tool availability

sdd-techdebt
└── depends on: Bash for complexity analysis tools

sdd-challenge prove
└── depends on: Git (for branch comparison), test runner

sdd-explain --format html
└── depends on: Write tool for file output
```

## Configuration Extensions

Add to `.sdd.yaml` schema:

```yaml
# Optional: Notes directory for /sdd-learn
notes_dir: notes/

# Optional: Techdebt thresholds
techdebt:
  duplicate_min_lines: 10
  complexity_threshold: 10
  max_function_lines: 50
```

## No New Agents

All features use existing agents:
- **critic**: Plan review, grill mode
- **simplifier**: Techdebt fix suggestions
- **spec-compliance**: Verify changes work

## No New Hooks

No hook modifications required. All features are command-driven.

## Security Considerations

- `sdd-learn`: Only writes to CLAUDE.md or configured notes_dir, confirms before writing
- `sdd-techdebt --fix`: Uses TDD (tests before changes), interactive confirmation
- `sdd-challenge prove`: Read-only branch comparison, no mutations
- `sdd-explain`: Output to specified file or display, no mutations to source
