## Rationale

1. **sdd-learn first**: Core workflow improvement that compounds over time — every lesson learned improves future sessions
2. **sdd-replan second**: Essential escape hatch when implementation struggles — prevents wasted effort
3. **sdd-techdebt third**: Session-end cleanup tool, independent of other features
4. **Plan-review fourth**: Enhances existing autopilot, independent of new commands
5. **sdd-challenge fifth**: Advanced prompting, less critical than core tools
6. **References (6-8)**: Documentation only, can be done in parallel
7. **sdd-explain last**: Nice-to-have, doesn't affect core workflow
