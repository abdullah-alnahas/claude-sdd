# /sdd-init

Interactive setup wizard for configuring SDD in your project.

> **New to SDD?** Try `/sdd-onboard` first — it explains the concepts before configuration.

## Usage

```
/sdd-init
```

## Behavior

1. Check if `.sdd.yaml` already exists
   - If exists: Ask "Overwrite existing config or merge new settings?"

2. Ask configuration questions using AskUserQuestion:

   **Question 1: Project type**
   - "Is this a new project or existing codebase?"
   - Options: [New project, Existing project]
   - Affects: initial phase recommendation

   **Question 2: Guardrail level**
   - "How strict should the guardrails be?"
   - Options: [Strict (recommended), Standard, Relaxed]
   - Affects: pre-implementation and scope-guard settings

   **Question 3: Default mode**
   - "What's your primary workflow?"
   - Options: [Building features (dev), Reviewing code (review), Exploring/research (research)]
   - Affects: mode setting

3. Generate minimal `.sdd.yaml` with only non-default values:

```yaml
# SDD Configuration
# Generated by /sdd-init

mode: dev  # Only if not default

guardrails:
  # Only include if non-default settings were chosen
```

4. Output summary:
   - What was configured
   - Recommended next command based on project type
   - Link to full config documentation

## Example Output

```
→ SDD: Config generated at .sdd.yaml

Settings:
  Mode: dev (default)
  Guardrails: standard

Next step: Run /sdd-status to see your project state
```

## Notes

- Does NOT require existing specs or architecture docs
- Safe to re-run (asks before overwriting)
- Minimal config = fewer merge conflicts
